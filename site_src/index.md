## How each day works

<div class="experience-grid">

<div class="experience-card">
  <span class="experience-icon">01</span>
  <strong>Learn</strong>
  <p>Start with the business or engineering requirement. Understand why the mechanism exists before configuring it.</p>
</div>

<div class="experience-card">
  <span class="experience-icon">02</span>
  <strong>See</strong>
  <p>Use focused Mermaid diagrams to follow who sends what, which component decides, and where trust changes.</p>
</div>

<div class="experience-card">
  <span class="experience-icon">03</span>
  <strong>Build</strong>
  <p>Run the flow in your own Okta environment using browser DevTools, Python helpers, Postman, and the course apps.</p>
</div>

<div class="experience-card">
  <span class="experience-icon">04</span>
  <strong>Break & prove</strong>
  <p>Trigger controlled failures, locate the last successful step, make one relevant change, and prove recovery.</p>
</div>

</div>

## Start with the system, not terminology

<div class="luxury-callout">

**The recurring troubleshooting question**

> What is the last step I can prove succeeded?

That question is used from browser redirects through token issuance, JWT validation, API authorization, refresh, Client Credentials, and Okta Management API automation.

</div>
